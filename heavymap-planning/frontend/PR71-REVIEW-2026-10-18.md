## 2. What #71 is

- `heavymap-planning/frontend/V0-SPEC.md`: Morgen's vision quoted in full, layouts A/B/C, six-band dossier anatomy, refusal copy, area shares (now flag-never-hide), lens model, OSM/Overpass options, basemap options, budgets, 8 questions for Morgen.
- `web/`: Vite 7 + MapLibre 6.14 + PMTiles 4.3. `fixtures.js` (3 invented parcels, inline six-band model), `dossier.js` (textContent-only renderer + JSON export), `map.js` (MapLibre, pmtiles protocol, conditional camera restore), `app.js` (lens/search/route). 768-byte synthetic PMTiles in `web/public/`. Node contract tests + 5 Playwright Chromium scenarios.
- `mockups/`: 3 Excalidraw scenes + PNG + SVG.

Overall: good craft and the right instincts (refusals visible, no vacancy assertion, textContent-only, failed fetch ≠ empty evidence, Range verified locally, no external calls, no deploy script). It is a **synthetic interaction prototype**. It does not consume the dossier v1 contract yet, so most contract items are backlog, not merge blockers.

## 3. Verdict

A few cheap doc and fixture fixes should ride along, so that #71 doesn't become stale front-end canon the moment the split rewrites the tree.

### 3.3 Not blockers (correct for a synthetic prototype; tracked as backlog)

- **Dossier contract not consumed.** There is no manifest load and no `shards/{id.slice(-2)}.json` fetch, dedupe or cache. The renderer reads an inline six-band model with per-claim `stamp`, not the v1 record (`area/coverage/roll/addresses/overlays/gaps`, `src/join/conf/label`). V0-SPEC l.45 says the bands are a *display* of the record, but there is no adapter. → backlog HM-03.
- **Front-end screening is pass-through.** `dossier.js` l.64–69 renders every key in `claim.stamp`, and `packet()` (`fixtures.js` l.400–411) exports `structuredClone(parcel.bands)` whole. That is fine for fixtures, but with real data the UI needs its own display/export allowlist plus a leak scan of `dist/` (defence in depth behind the IA allowlist). → HM-04.
- **Gap vocabulary absent.** Only the three refusal codes exist (`fixtures.js` l.413–418; `contract.test.js` l.32–35). None of the 9 gap types are present, there are no `gaps_ledger` lookups, and there is no placeholder-ARN case (`coverage.status = arn_invalid`, value not shown). → HM-05.
- **Withheld / held-identifying-info indicators absent**, and so are `publish_visibility` states. → HM-06.
- **Slivers.** The spec is aligned (flag, never hide). The fixtures contain no sliver row, so the prototype doesn't demonstrate it. → HM-07.
- **Run records (NA-308), address-no-parcel list (NA-309), experience profiles (NA-310) and the browser notice (NA-305)** are all absent. The tests are Chromium-only (`playwright.config.js`), and the fixture PMTiles is uncompressed, so the Pages `range_gzip` / Firefox problem (PMTiles #584) is untested. → HM-08…HM-11, HM-15.
- **Attribution off**: `map.js` l.114 `attributionControl: false`. That is fine with no external tiles, but required before any OSM/Stadia/Protomaps basemap. → NA-37.
- **AGENTS.md "UI chrome stays deferred"** (main) conflicts with #71 and with this kickoff. V0-SPEC l.19 (Scope and authority) records a prompt-scoped override. Rewrite it in the HM copy of AGENTS.md at the split.
